# DomainScan - технический аудит v0.8.1

Обновлено: 2026-10-06. Документ описывает текущий код и локальную проверку. Состояние опубликованного
выпуска и CI доступно на странице [релизов](https://github.com/mazixs/DomainScan/releases).

## Проверка

- `npm run verify`: синтаксис, манифест, локали, PSL, согласованность версий и запись changelog.
- `npm test`: 163 модульных и worker-теста.
- `npm run test:e2e`: 25 сценариев с распакованным расширением в Chromium.
- `node scripts/benchmark.mjs`: синтетические замеры накопления и группировки данных.

Локальные проверки не доказывают совместимость со всеми сайтами. Для приемки выпуска нужно также
проверить CI, версию манифеста в опубликованном ZIP, целостность архива и работу извлеченного пакета.

## Исправления

### Совместимость и настройки

Ранее глобальное выключение API снимало регистрацию MAIN-world probe, но ISOLATED-world relay
продолжал внедряться из манифеста. Теперь оба скрипта регистрируются динамически с одинаковыми
исключениями, а глобальное выключение снимает обе регистрации. Новые документы не получают
скриптов DomainScan; сетевые домены и IP продолжают собираться.

Соединение probe и relay работает при любом порядке запуска и сохраняет ранние сигналы API.
Ошибки применения настроек видны в панели. Примененная, но не сохраненная настройка отличается
от настройки, которую не удалось применить. Отдельно проверены загрузка настроек и повторная попытка.

В обезличенной ручной проверке после обновления расширения, глобального выключения API и открытия
новых документов блокировка защищенного сайта не повторилась. Этот результат не устанавливает
конкретный триггер защиты и не гарантирует долговременную совместимость. Подробности и порядок
проверки описаны в [заметке о совместимости](COMPATIBILITY.md).

### Состояние, пауза и очистка

Ответ с IP привязан к поколению записи вкладки, а не только к имени сайта. Поздний ответ не может
попасть в запись после очистки, смены сайта или возврата на тот же сайт. Поколение сохраняется при
нормализации состояния; очистка также удаляет ожидающую навигацию.

Запросы, начатые во время паузы, не получают IP после возобновления. Документ, запрошенный во время
паузы, обновляет идентичность сайта без ретроспективного добавления наблюдения.

Очистка сбрасывает контрольную отметку во всех открытых панелях, даже если временные метки совпали.
Снимки состояния для панели, хранилища и отметки остаются неизменными при последующих обновлениях.

### Производительность

Фоновое накопление использует отдельный черновик назначений для каждой вкладки. Словарь копируется
при первой записи после публикации снимка, а не на каждом запросе. Чистые функции переходов остаются
неизменяемыми. Группировка собирает IP через один Set на группу и завершает массив один раз.

Синтетический замер на Node.js, медиана трех прогонов на одном наборе данных:

| Назначения | Повторные события | Полное копирование, мс | Аккумулятор, мс | Группировка IP, мс |
| --- | --- | --- | --- | --- |
| 1 000 | 1 000 | 210.91 | 2.84 | 5.04 |
| 5 000 | 1 000 | 1590.70 | 5.60 | 26.72 |
| 10 000 | 1 000 | 3191.47 | 4.73 | 36.75 |

Воспроизведение: `node scripts/benchmark.mjs`. Сравнивается неизменяемый переход с новым
аккумулятором, который публикует один снимок после серии событий. Реальная частота публикации,
сериализация и нагрузка браузера влияют на выигрыш. Это замер обработки данных, а не скорости сети
или загрузки сайта; числа зависят от среды исполнения.

## Сохраняемые гарантии

- Состояния вкладок независимы; идентичность сайта берется из подтвержденной навигации.
- Домены определяются по полному ICANN + PRIVATE Public Suffix List.
- У назначения сохраняются все замеченные IP, транспорты, категории запросов и URL-порты.
- Пауза не мешает обработать навигацию, фильтры и группировка не удаляют исходные наблюдения.
- Трафик service worker относится только к вкладкам с тем же origin и явно помечается.
- Сигналы API содержат только факт обращения; возвращаемые значения не сохраняются.
- Пакет собирается после проверок по списку разрешенных файлов. ZIP и описание релиза проверяются
  по SHA-256, а описание берется из [CHANGELOG.md](../CHANGELOG.md).

## Ограничения

1. Включенное наблюдение API меняет функции страницы и обнаружимо из другого контекста.
2. Выключение влияет на будущие документы и не отменяет уже внедренные изменения. Требуется
   закрыть затронутые вкладки и открыть их заново. Пауза записи не снимает инструментирование.
3. Исключение одного сайта применяется к URL каждого фрейма. Встроенные страницы других сайтов
   могут оставаться инструментированными; для режима без скриптов нужно глобально выключить API.
4. Chrome не всегда сообщает IP, в том числе для кешированных ответов.
5. `webRequest` видит открытие WebSocket, но не сообщения, и не заменяет наблюдение сокетов.
   Показываемые порты взяты из URL; QUIC/UDP/WebRTC-трафик не является полной сетевой телеметрией.
6. Сигнал API доказывает обращение, но не намерение, успех или полезность результата.
7. За пределами квоты `storage.session` живая запись продолжается, но последние наблюдения могут
   потеряться после перезапуска worker. Панель предупреждает о хранилище и позволяет экспортировать JSON.
8. Доступность экранным диктором и установка через магазин требуют отдельной проверки.
